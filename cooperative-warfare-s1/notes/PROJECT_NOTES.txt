  Plus [hid] mnk_mode=true, mnk_mouse=true, mnk_sensitivity=6.0 (1.0 was far too slow).
- What each test showed: default render targets (RTV) = black 3D + flicker. ROV path = correct picture (needs RTX-class GPU with ROV; RTX 3050 ok).
  ROV + async OFF = looks frozen (blocking shader compiles, 0 FPS) - avoid. readback_memexport = no change. readback_resolve='full' = black screen.
  readback_resolve='fast' (previous-frame readback) = FIXES the exposure flicker / white-out when the VTOL doors open.
  Not helpful / untested: the 7 NX1 options (already default false), submit_on_primary_buffer_end, fuzzy alpha, native_2x_msaa off, float24 depth options.
- Value types: readback_resolve is a STRING (none/fast/some/full) in gpu.xenos; gpu.d3d12 readback_resolve is a bool (do not use). CLI only accepts game_data_root update_data_root protect_zero mnk_mode log_level.
- Performance: ~15-18 FPS in the VTOL, 7-14 in combat, dips to 4 in big explosions (ROV cost). F3 overlay = stats, F10 = SDK settings.
- Whole Fusion level plays (VTOL, rappel drop, courtyard firefight, checkpoints).
- FASTFILE FORMAT (zone files in the game dir, SP = unsigned):
  header: "IWffu100" (SP, unsigned) / "IWff0100" (MP, signed, not yet decoded), then u32 version 0x4f2, u32 0x404, 8-byte build FILETIME (May 2013), u32 1.
  small files: u32 0, u32 size, u32 size, then ONE zlib stream (78 01) from byte 40. decompressed = XFile header.
  XFile header (big-endian): u32 size, u32 externalSize, u32 blockSize[7], then XAssetList {u32 scriptStringCount, ptr strings(-1), u32 assetCount, ptr assets(-1)},
  then 1 spare u32, scriptStringCount pointers (-1/0), the strings, then assetCount x (u32 type, ptr). Rawfile body = {name -1, compressedLen, len, buffer -1} + name + zlib data.
  big files (common.ff, fusion.ff): ~19 KB block table after the header, then a first huge zlib stream (the XFile) followed by many small zlib streams (stream data).
  asset type ids seen: 2 (probably xanim), 4, 5, 9, 26 (menu file in patch.ff), 29, 33, 40 = rawfile, 42 = stringtable (first asset "sp/specopstable.csv"), ...
  The game also probes update:\patch_<map>.ff and patch_ui.ff (update_data_root) = a hook point for our own patch fastfile; patch.ff is a valid 93-byte empty patch.
- common.ff contents (extracted lists in s1_ff_findings_v01.zip): 545 script strings, 7778 assets. Contains Special Ops system: so_*.gsc names, popmenu_specialops_splitscreen_difficulty_p1/p2,
  LiveParty* uiScripts, popup_waitforpartymembers, setNetCoOpDifficulty, COOP_* error strings (HOST_END_GAME, WAITINGFORPLAYER, WRONGCHECKSUM...), SCRIPT_COOP_REVIVE, devmap dvarstring(ui_load_so_level).
  Extracted GSC source (s1_common_scripts_extracted.zip) is plain text = the dev build keeps source; unknown yet whether the game compiles it at load.
- MP files exist (mp_dam.ff, *_mp.ff, signed IWff0100). common_mp.ff (360 MB) received, not decoded yet.
